    경비가 왜 순공사원가 칸에 들어가 있을까?

    자세히 보기

    공고 23건의 원문을 하나씩 열어 DB 값과 맞춰 보다가 이상한 걸 발견했어요. SRM에서 받은 값이 순공사원가가 아니라 '경비'였어요. 컬럼을 나누고, 이미 잘못 저장된 데이터는 따로 고쳤어요.

    • SRM overHeadCostAmount 값이 공고문 원문의 '경비' 칸과 같다는 걸 공사 15건에서 확인
    • overhead_cost_amount 컬럼을 추가하고, 순공사원가는 확인 전까지 비워 둠
    • 기존 DB 957건 중 1건이 대상이었고, DB를 백업한 뒤 한 번에 고치는 정정 스크립트를 만듦
    • 검증 일지 ↗
  • Bidmate_AI

    수집이 중간에 끊기면 처음부터 다시 해야 할까?

    자세히 보기

    SRM은 요청이 몰리면 막혀서, 실제로 공고 16건쯤마다 끊겼어요. 그래서 공고 하나를 끝낼 때마다 저장하게 바꿨어요. 다시 실행하면 못 끝낸 공고부터 이어서 해요.

    • 공고 1건 상세 수집이 끝날 때마다 커밋하고, 다음 실행은 미완료 공고만 고름
    • 차단이 의심되면 10분 쉬었다가 이어서 수집
    • 매일 12시 Windows 작업 스케줄러로 자동 실행, 결과는 collect_run 테이블에 남김
    • 수집기 문서 ↗
  • Bidmate_AI

    정정된 공고는 어떻게 알아챌까?

    자세히 보기

    공식 API에는 '수정된 시각'으로 찾는 기능이 없었어요. 그래서 처음 받은 원본을 저장해 두고 새로 받은 값과 비교해요. 그래도 못 찾는 경우가 있어서, 그건 문서에 그대로 적어 뒀어요.

    • 저장한 api_raw와 비교해 신규 / 정정·첨부 변경 / 기본정보 갱신으로 나누고, 정정 공고만 다시 수집
    • 공고일은 그대로 두고 내용만 바뀐 수정은 감지할 수 없어서 --srm-revision-check 옵션으로 보완
    • DB 스키마 문서 ↗

    모니터링 요청까지 공격이라고?

    자세히 보기

    트래픽이 갑자기 늘면 공격인지 화제성 유입인지 AI가 구분하게 만들었어요. 그런데 저희가 쓰는 모니터링 API 호출까지 공격으로 판단하더라고요. 판단할 경로를 실제 공격이 들어오는 곳으로 좁혀서 고쳤어요.

    • Lambda 도구 8종과 Bedrock AgentCore 시스템 프롬프트를 맡음
    • AI가 상황에 따라 보안 판별을 건너뛰는 문제가 있어서 "보안 판별을 항상 먼저" 규칙으로 고정
    • "Unknown tool" 오류가 반복돼서 Gateway Tool Schema를 Lambda 함수와 1:1로 맞춤

Main Prompt

  1. 01원문과 대조하기

    Check every value against the original document before I use it. Mark anything you can't confirm instead of guessing.

  2. 02추측 전에 묻기

    If a requirement is unclear, state your assumptions or ask first. If there are several interpretations, don't silently pick one.

  3. 03요청한 것만 만들기

    Implement only what I asked, as simply as possible. No extra features, abstractions, or unnecessary error handling.

  4. 04관련된 줄만 고치기

    When editing existing code, change only the lines related to the request and follow the existing style. Mention unrelated issues instead of fixing them.

  5. 05단계마다 검증하기

    For multi-step work, show a short plan as "step → how to verify" first. For bug fixes, start with a test that reproduces the bug.

These are the rules I give every AI coding tool I work with.
